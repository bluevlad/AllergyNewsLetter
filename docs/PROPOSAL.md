# AllergyNewsLetter 기술 제안서

> 알러지 관련 뉴스 및 논문 일일 브리핑 자동화 서비스

## 1. 프로젝트 개요

### 1.1 목적
알러지 환자, 의료진, 연구자를 위한 **알러지 관련 최신 뉴스 및 논문 정보**를 매일 아침 이메일로 제공하는 자동화 서비스

### 1.2 주요 기능
- **뉴스 자동 수집**: 네이버 뉴스에서 알러지 관련 기사 수집
- **논문 자동 수집**: PubMed에서 최신 알러지 연구 논문 수집
- **AI 기반 분석**: 기사/논문 요약, 카테고리 분류, 중요도 산정
- **뉴스레터 발송**: HTML 형태의 일일 브리핑 자동 발송

### 1.3 참조 프로젝트
- **HealthPulse** (`C:\GIT\HealthPulse`): 구조 및 코드 80% 재사용

## 3. 기술 스택

| 구성요소 | 기술 | 비고 |
|---------|------|------|
| 언어 | Python 3.10+ | HealthPulse와 동일 |
| 뉴스 수집 | 네이버 검색 API | HealthPulse 코드 재사용 |
| 논문 수집 | PubMed E-utilities API | 신규 개발 |
| AI 요약 | Ollama (로컬) / Claude API | 선택적 |
| 스케줄러 | APScheduler | HealthPulse와 동일 |
| DB | SQLite | 경량화 |
| 이메일 | Gmail SMTP | HealthPulse와 동일 |
| 배포 | Docker + Windows Task Scheduler | 로컬 서버 |

## 6. 카테고리 분류 체계

| 카테고리 | 설명 | 예시 |
|---------|------|------|
| `CLINICAL` | 임상/치료 정보 | 신약 승인, 치료 가이드라인 |
| `RESEARCH` | 연구/학술 | 논문, 학회 발표 |
| `LIFESTYLE` | 생활/관리 | 식단, 환경 관리 팁 |
| `MARKET` | 산업/시장 | 제약사 동향, 시장 분석 |
| `REGULATION` | 규제/정책 | 식약처, FDA 승인 |
| `OTHER` | 기타 | 분류 불가 |

## 7. 개발 방안

### 방안 A: 순차적 세션 기반 개발

```
[세션 1] Opus - 설계 및 기반 구축
├─ 프로젝트 구조 설계
├─ HealthPulse에서 공통 모듈 추출
├─ DB 모델 정의
└─ 핵심 인터페이스 작성

[세션 2] Opus/Sonnet - 수집기 구현
├─ NaverNewsCollector 복사 및 키워드 수정 (Sonnet)
├─ PubMedCollector 신규 구현 (Opus)
└─ 수집기 통합 테스트

[세션 3] Sonnet - 처리기/리포터 구현
├─ AllergyClassifier 구현
├─ 이메일 템플릿 수정
└─ 발송 로직 구현

[세션 4] Opus - 통합 및 배포
├─ 전체 파이프라인 테스트
├─ Docker 설정
└─ 스케줄러 설정
```

**특징**:
- 단계별 명확한 구분
- 각 세션 30분~1시간
- 예상 세션: 4회

**장점**:
- 진행 상황 추적 용이
- 단계별 검증 가능

**단점**:
- 전체 소요 시간 길어짐
- 세션 간 컨텍스트 전달 필요
